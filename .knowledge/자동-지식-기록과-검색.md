# 자동 지식 기록과 문서 검색

## 현재 동작

2026-09-11 `ac99985` 소스 기준이다. `/auto-knowledge`로 프로젝트의 자동 기록 상태를 선택한다. 켜짐 표시는 컴포저와 설정 사이드패널에 반영되지만 문서 기록의 성공을 뜻하지 않는다.

- **읽기:** 켜짐·꺼짐과 관계없이 기본 지침은 [knowledge-index.md](knowledge-index.md)를 먼저 읽고 필요한 문서의 관련 부분만 읽도록 요구한다. 인덱스가 없으면 파일명·검색으로 찾는다.
- **쓰기:** 켜짐이면 반복 실수·검증된 해결법·재사용할 확정 정보를 기존 주제 문서에 합치고 인덱스도 갱신하도록 지시한다. 꺼짐이면 자동 생성·갱신을 하지 않되 사용자의 명시적 기록 요청은 수행한다. 역할의 쓰기 제한과 사용자 지시는 계속 적용된다.
- **전달:** [src/main.rs](../src/main.rs)의 `DEVEZ_INSTRUCTIONS`·`CLAUDE_DEVEZ_INSTRUCTIONS`에 읽기 규칙이 있고, `auto_knowledge_context`는 매 요청의 현재 기록 상태를 만든다. [src/backend.rs](../src/backend.rs)가 제공자별 요청 형태로 전달한다.
- **실행 주체:** LLM이 파일 도구로 문서를 읽고 쓴다. 앱이 문서 본문을 자동 요약·검색해 주입하거나 임베딩·그래프를 만드는 기능은 이 경로에 없다. 지침 전달 검사와 실제 모델의 문서 읽기·쓰기 성공은 구분한다.

## 프로젝트별 저장과 오류

[src/state.rs](../src/state.rs)의 `project_settings_key`, `read_project_auto_knowledge_at`, `write_project_auto_knowledge_at`가 기준이다.

- Windows는 `%APPDATA%/DevezVibe/project-auto-knowledge.json`에 정규화한 작업 폴더별 불리언 값을 저장한다. APPDATA가 없으면 HOME 아래 `.config/devez-vibe`를 사용한다.
- 저장값 없음·읽기 실패·파싱 실패 시 기본은 꺼짐이다. 쓰기에서는 손상된 기존 JSON을 덮어쓰지 않고 오류를 반환한다.
- 다른 창의 저장과 충돌하지 않도록 잠금을 잡고 임시 파일을 교체한다. Windows 폴더 대소문자·구분자를 정규화한다.
- 설정 저장 실패 시 경고를 표시한다. 선택한 메모리 상태가 자동으로 이전 값으로 돌아가는 처리는 없으므로, 저장 성공과 화면의 현재 선택을 동일하게 보지 않는다.
- 새 프로젝트·작업 트리는 해당 작업 폴더의 저장값을 사용한다. 기존 프로젝트의 켜짐 상태가 모든 폴더에 전역 적용되는 설정은 아니다.

## 검색·기록 기준

색인의 제목·설명으로 문서를 고른 뒤 관련 절을 확인한다. 후보를 확신하기 어렵거나 근거가 부족하면 증상·오류 문구·기술 식별자로 본문을 검색한다. 검색 결과에 등장했다는 이유만으로 현재 사실이라고 단정하지 않는다.

문서 설명에는 실제 질문에 쓰이는 주요 증상을 넣고, 원인·관련 구현·검증 범위·과거 기록을 구분한다. 날짜가 붙은 미배포 기록을 지우기보다 후속 배포 기록을 연결한다. 개인정보·비밀정보·추측·일회성 임시 상태를 지식으로 적재하지 않는다.

## 검증과 한계


고정 검색어 10개로 시행한 작은 자체 점검은 [검색 보고서](../artifacts/knowledge-search-evaluation/README.md)를 참고한다. 이것은 실제 LLM 정확도나 임베딩·그래프 비교 시험이 아니다.

2026-09-11 [전체 문서 점검](../artifacts/knowledge-search-evaluation/document-audit.md)에서 색인의 주요 증상 누락과 오래된 현재형 설명을 보완했다. 같은 질문의 색인 후보 포함 수는 7/10에서 10/10으로 바뀌었으며, 알려진 질문에 맞춘 정비이므로 일반 정확도 개선으로 해석하지 않는다.
