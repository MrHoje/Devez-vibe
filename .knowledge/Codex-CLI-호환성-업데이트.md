# Codex CLI 호환성 업데이트 절차

## 목적

DevezCLI는 공식 `codex app-server`를 사용하는 독립 UI다. Codex CLI가 업데이트되면
프로토콜·모델 카탈로그·이벤트 변화가 DevezCLI에 영향을 주는지 확인하고, 필요할 때만
코드를 최신화한다.

자동 CI 감시는 사용하지 않는다. 유지보수자는 대화에서 다음처럼 지시한다.

```text
최신 Codex CLI 확인해서 DevezCLI에 반영해
Codex 업데이트 영향 확인해
Codex 0.x.y 기준으로 호환성 업데이트해
```

## 작업 순서

1. 현재 설치 버전과 npm 최신 버전을 확인한다.

   ```powershell
   codex --version
   npm view @openai/codex version
   ```

2. 최신 Codex의 공개 변경 사항과 app-server 스키마를 확인한다.

   ```powershell
   codex app-server generate-ts --experimental --out <임시-폴더>
   ```

   최신 버전이 설치되지 않았다면 `npm exec --yes --package=@openai/codex@<버전> -- codex`
   로 실행한다.

3. DevezCLI에서 영향을 받을 지점을 대조한다.

   - JSON-RPC 연결·초기화: `src/app_server.rs`
   - 스레드·모델·승인 요청: `src/main.rs`
   - 이벤트 해석과 UI 상태: `src/state.rs`
   - Plugin·MCP·Marketplace: `src/integrations.rs`
   - 세션 재개 형식: `src/rollout.rs`

4. 영향이 없으면 확인한 Codex 버전과 판단 근거를 이 문서의 `확인 기록`에 추가한다.
   영향이 있으면 필요한 코드를 수정하고 관련 테스트를 추가한다.

5. 다음을 검증한다.

   ```powershell
   cargo test
   ```

   가능하면 실제 최신 Codex로 `initialize`, 모델 목록 조회, 새 스레드 시작을 확인한다.

6. 변경 사항과 검증 결과를 사용자에게 간단히 보고한다. 이 문서의 확인 기록도 갱신한다.

## 신모델 반영

- Devez Vibe는 `PATH`의 `codex`를 실행하므로 CLI 갱신만으로 모델 목록이 나타나는지 먼저 확인한다. 목록 형식이 그대로라면 Devez Vibe 배포는 필요 없다.
- 비용 표시는 별도이므로 `.knowledge/토큰사용량-단가-갱신.md` 절차에 따라 구체적인 티어를 일반 계열보다 먼저 배치한다.
- 짧은 모델 검색어가 필요하면 모델 별칭을, 새 계열의 시각 구분이 필요하면 렌더러 색상을 함께 갱신한다.
- 릴리스 노트의 기능 항목뿐 아니라 기본값 변경도 확인한다. 선택 활성화로 바뀐 도구는 app-server 실행 설정에서 명시적으로 켜지 않으면 UI 기능이 조용히 사라질 수 있다.

## 판단 기준

- **반영 필요**: DevezCLI가 호출하는 메서드·보내는 파라미터·해석하는 이벤트·모델 목록
  형식이 변경됨.
- **반영 불필요**: UI가 사용하지 않는 새 기능이 추가됐거나 기존 동작이 호환됨.
- **주의 필요**: app-server 스키마는 바뀌지 않았지만 Codex CLI의 사용자 경험·명령 의미가
  달라져 DevezCLI의 Codex 정렬 목표에 영향을 줌.

## 확인 기록

### 2026-09-10 필수 호환성 수정 및 검수 — 미배포

- 병렬 구현 범위는 승인된 네 항목뿐이다. Codex 요청 분기와 MCP 표시, Claude SDK 상향·사용량 최적화를 분리 구현하고 독립 읽기 전용 검수와 별도 MCP 실행 검증을 수행했다. 의도적인 질문 중단 방식·권한 정책은 유지했다.
- `openai/userVerification`은 일반 허용 창으로 표시하지 않고 지원하지 않는 환경임을 안내한 뒤 `decline`한다. 알 수 없는 문자열·숫자·명시적 null 모드도 거절한다. 이미 다른 입력을 기다리는 경우에는 기존 입력을 보존하고 새 요청만 `cancel`한다. 기존 `form`, `openai/form`, `openaiForm`, 생략 모드와 URL 흐름은 유지한다. 인증 challenge는 안내에 출력하지 않는다.
- 실제 Windows Codex 0.154.0의 `userVerification/status`는 `-32603`, `unavailable/providerUnavailable`, `User verification is not available in this build.`를 반환했다. 공식 `codex-rs/user-verification/src/lib.rs`의 네이티브 제공자도 macOS에 한정된다. 생체 인증 등록·검증·설정 변경은 수행하지 않았고 성공 경로는 지원한다고 주장하지 않는다.
- MCP 목록과 상세 화면에 `runtimeStatus`, `toolsError`를 반영했다. 시작 전·연결 중·연결됨·로그인 필요·실패·취소·비활성을 구분하고, null/미지 런타임 상태는 미확인으로 표시한다. 필드가 없는 구버전과 Claude의 `status/error` 해석은 유지한다. 도구 조회 실패는 정상적인 도구 0개와 구분해 오류 사유를 제공한다.
- 시작 실패 복구는 기존 `startupStatus/updated`의 목록 갱신 경로를 유지한다. 재조회된 정상 목록으로 과거 실패를 지우는 시험을 추가했다. 독립 검수에서 시험 데이터의 잘못된 목록 상태 `ready`를 찾아 `connected`로 정정하고 실제 연결 표시까지 검사하도록 보강했다. 시작 알림의 `ready`와 목록의 `connected`를 혼동하지 않는다.
- 실제 MCP 검증은 임시 `CODEX_HOME`과 제어 가능한 MCP 서버를 사용했다. 같은 Codex 프로세스·같은 임시 대화·같은 구성에서 도구 조회 실패(`runtimeStatus: failed`, 구체 `toolsError`) → `config/mcpServer/reload` → 정상 빈 목록(`connected`, `toolsError: null`, `tools: {}`)을 확인했다. 정상 도구 1개와 threadId 없는 조회의 `runtimeStatus: null`도 확인했다. 사용자 설정·인증을 변경하지 않았으며 시험 프로세스 트리 종료 후 잔여 프로세스가 없음을 확인했다.
- 실제 응답 근거는 `%TEMP%/devez-mcp-qa-e5cfac27046741d7b39871fe6a6cb9ed/results.json`과 `recovery-results.json`에 있다. 화면 표시 자체는 Rust 상태·목록·상세 시험으로 확인했으며 실제 터미널을 직접 조작한 검증은 아니다.
- 최종 검증 결과:
  - 일반 시험 1,276개 통과, 실패 0, 기본 제외 13개. 이번 수정의 새 Rust 회귀시험은 6개이며, 작업 중 별도로 유입된 UI 변경의 시험 2개도 최종 통합 실행에 포함됐다.
  - `cargo test live_codex_ -- --ignored --nocapture --test-threads=2`: 실제 검사 10개 모두 통과(528.72초). 네 모델·23개 추론 수준의 작업 목록/질문/마우스 응답, 자연어 직접 입력, 비동기 질문 복구, 네 모델의 90초 무응답·답변 후 실행·취소·새 작업 재개, 연결 종료, 과거 계획 모드 대화 재개, 권한 적용을 포함한다.
  - 실제 Claude 자동 모드 검사 1개와 최신 SDK 번들의 시작·대화·재개·즉시 중단·후속 대화 통과. 세부 내용은 Claude 호환성 문서를 따른다.
  - Release 빌드·실행 버전 1.8.17 확인, 기존 사용하지 않는 코드 경고 3건은 유지. 독립 검수에서 남은 제품 결함 없음. 별도 터미널 화면 검사 2개는 실행하지 않았다.
  - Codex 기준을 0.154.0으로 갱신한 뒤 `--mode fixed --version 0.154.0` 재검사에서 스키마 일치 확인. SHA-256은 `0273c95bda7341893a89cb61cbde3127ec4f269100db376978724040777b5d10`이다. 비교용 schema-current.ts는 기준 갱신 과정에서 제거됐고 같은 최신 내용은 schema.ts에 있다.
- 작업 중 별도로 추가된 `src/renderer.rs`의 하위 에이전트 행 표시와 `src/main.rs`의 문단 간격 지침 변경은 되돌리지 않았으며 이번 네 항목의 독립 검수 범위와 구분한다. 최종 일반 시험은 이를 포함한 소스로 수행했고, 마지막 소스 변경을 포함한 Release 재빌드도 통과했다. 실제 Codex 질문 전체 검사는 별도 지침 변경 전 소스로 통과했다.
- 배포 대기 노트를 작성했다. 제품 버전 상향·커밋·푸시·공개 배포는 하지 않았으며 아래 내용은 초기 점검과 계획 당시 기록이다.

### 2026-09-10 Codex 0.154.0 최신 기능 점검 — 구현 전

#### 승인된 후속 구현 계획

- 사용자 요청: 의도적으로 다른 동작과 선택 기능을 제외한 네 항목을 모두 구현하고 병렬 작업·검수까지 수행한다. 구현 대상은 사용자 인증 요청 분기, MCP 상태/도구 조회 실패 표시, Claude SDK 0.3.267 상향, Claude 사용량 조회의 불필요한 대화 파일 스캔 생략이다.
- 병렬 분담: 인증 담당은 요청 수신·응답과 입력 시험, MCP 담당은 `src/integrations.rs` 파싱·상태 표시·복구 시험, Claude 담당은 npm 의존성·브리지·관련 시험을 맡는다. 루트는 통합 검증·문서·스키마 기준을 관리한다.
- 인증 구현 판단: 실제 플랫폼 지원과 계약을 확인한다. 지원하지 않는 인증을 일반 허용으로 처리하지 않으며, 이 환경에서 인증을 지원하지 않으면 이유를 알리고 요청을 명시적으로 거절한다. 실제 사용자의 생체 인증 등록이나 기존 설정을 변경하는 검증은 하지 않는다.
- 검증 기준: 각 수정의 실패 입력과 정상 복구 시험, 기존 폼·질문·Claude 상태 호환, 최신 SDK 브리지 검사, Rust 전체 시험, 최신 Codex 실제 모델 질문·재개 검사, Release 빌드, 독립 검수와 발견 문제 재검증을 수행한다. 인증 장치·계정 자격 때문에 검증할 수 없는 경로는 별도 기록한다.
- 제외 범위: 비동기 질문의 중단 방식, 권한 정책, worktree/공유 서버 등 별도 기능은 유지한다. 이번 요청에는 공개 배포가 포함되지 않으므로 버전·공개 패키지는 변경하지 않는다.

- 기준 소스는 `c74b0f1`(Devez Vibe 1.8.17), npm 최신과 설치 CLI는 모두 `0.154.0`이다. 공식 릴리스 날짜는 2026-09-09다.
- 공식 근거: [Codex 변경 이력](https://learn.chatgpt.com/docs/changelog), [0.154.0 릴리스](https://github.com/openai/codex/releases/tag/rust-v0.154.0), 해당 CLI가 생성한 실험 기능 포함 TypeScript 스키마.
- `node scripts/check-codex-compatibility.mjs --mode latest`는 기존 `0.153.2` 기준과 달라 종료 코드 1을 반환했다. 생성 타입 파일 20개 추가, 삭제 없음. 전체 스키마 차이는 기존 기능의 실패를 뜻하지 않는다. 기준은 갱신하지 않았고 `artifacts/codex-compatibility/schema-current.ts`와 비교 보고서를 남겼다.
- 현재 스키마 SHA-256: `0273c95bda7341893a89cb61cbde3127ec4f269100db376978724040777b5d10`.

### 권한의 단계적 전환

- 사용자 지시에 따라 Codex는 새 대화·재개·분기·새 턴에서 전체 접근(`:danger-full-access`)과 승인 요청 없음(`never`)을 먼저 적용한다. 권한 프로필·격리 모드·승인 정책이 정책상 거절된 경우에만 작업 폴더 수정(`:workspace`), 읽기 전용(`:read-only`) 순으로 재시도한다.
- 낮춘 모드에서는 실행 중인 Codex의 승인 정책을 상속한다. 인증 실패·연결 오류·명령 실행 실패·일반 거절은 재시도하지 않으므로 이미 실행한 명령을 반복하는 복구가 아니다. 모두 거절되면 오류를 그대로 알린다.
- 역할이 명시한 읽기 전용 제한은 그대로 적용한다. 상태 표시와 `/permissions`는 요청한 최고 모드가 아니라 실제 성공한 모드를 보여 준다. 새 턴에서는 최고 허용 모드를 다시 우선 시도한다.
- 설치된 0.153.4의 `permissionProfile/list`에서 세 내장 프로필을 확인했다. 조직 제한이 없는 현재 계정에서는 직접 낮은 프로필 적용과 최고 모드 적용을 실제 API로 확인하며, 정책 거절과 단계적 재시도는 모의 응답으로 검사한다.
- 거절 판정은 권한 설정 관련 오류에 한정한다. Codex 갱신 시 오류 문구가 달라지면 `permission_configuration_rejected`와 재시도 검사를 함께 대조한다.
- 일반 검사 1,224개와 Claude 브리지 자체 검사가 통과했다. 실제 Codex의 새 대화·첫 턴·저장된 대화 재개에서 전체 접근과 승인 요청 없음이 적용되는 것을 확인했다. 모든 단계 거절 시 오류 유지, 승인 정책 거절 시 하향 전환, 인증·명령 오류 미재시도도 모의 응답으로 검사한다.
- 권한 변경 후 네 모델의 자연어 질문·직접 입력·최종 응답 전달도 재검증했고, Release 빌드가 통과했다. 권한 변경은 아직 배포하지 않았다.

### 2026-09-09 질문 기능 전체 흐름 재점검

- 범위는 Codex 질문의 수신·선택지·직접 입력·키보드·마우스·전송·중복 알림·취소·연결 종료·재개다. 공통 질문 화면과 상태 로직은 일반 시험으로 함께 검사하며, Claude 실제 모델은 이번 실제 실행 범위에 포함하지 않는다.
- 1.8.6의 일반 시험이 모두 통과해도 아래 결함은 남아 있었다. 기존 검증은 도구 이름을 지정한 단순 질문과 정상 답변에 치우쳤고, 실제 전송 입력·전송 실패 후 상태·중복 이벤트·중단 완료와 확인 입력의 순서를 검사하지 않았다.

### 선택 질문의 응답 대기

- Codex 0.153.4의 기본 질문은 `features.default_mode_request_user_input=true`로 활성화한다. 매 `turn/start`에 `collaborationMode.mode: default`를 지정하고 질문 전용 지침을 함께 전달한다. 기존 1.8.4 대화에 남은 계획 모드도 여기서 되돌린다. 선택 모델·추론 수준·역할별 쓰기 권한은 유지하고 `turn/steer`는 현재 설정을 바꾸지 않는다.
- **1.8.4 판단 정정:** `isBlocking: false`를 모델이 답변 전에 실행을 계속한다는 뜻으로 해석했으나, 이는 화면 표시 방식의 힌트다. 기본 질문 RPC는 일반 모드에서도 사용자의 응답을 보낼 때까지 도구 결과를 반환하지 않는다. 계획 모드를 강제하면 `update_plan`이 금지되는 별도의 문제가 있으므로 그 방식을 사용하지 않는다.
- Astra의 `request_user_input_async`는 별개다. `agentMessage`의 `delivery: async`와 `questions`로 전달되며 이를 기본 질문 RPC와 혼동하지 않는다. 비동기 질문은 현재 턴을 중단하고 기존 질문 창에 보존한다. 턴 종료 확인 후 사용자가 제출한 답변을 같은 대화의 새 사용자 입력으로 전달한다. 응답할 RPC가 없으므로 가짜 RPC 답변이나 빈 답변을 보내지 않는다. 기본 질문 RPC가 답변 없이 해제되는 경우에는 기존 중단 처리를 유지한다.
- 1.8.5의 비동기 질문 일괄 실패 처리는 질문을 표시하지 못하는 회귀였다. 기본 질문만 명시적으로 호출하도록 유도한 검증으로는 비동기 경로를 검증할 수 없다. `cargo test live_codex_async_question_recovery -- --ignored --nocapture`로 실제 Astra 비동기 질문·턴 중단·10초 대기·답변 후 재개를 별도 검증한다. 실제 응답의 `options: null`도 정상적인 직접 입력 질문으로 취급한다.
- 비동기 질문은 수신 후 턴 중단으로 대기하므로 이미 시작된 도구 실행까지 되돌린다는 보장은 없다. 기본 질문 RPC 우선 지침은 유지한다.
- 수정 후 일반 시험 1,211개와 실제 Codex 0.153.4·Astra의 비동기 질문 복구 시험을 통과했다. 별도 실행형 시험 8개는 일반 시험에서 제외되며, 이 중 새 비동기 복구 시험만 이번에 실행했다. 1.8.6으로 배포했으며 공개 실행 파일과 빌드 산출물의 SHA-256 일치 및 설치 후 실행 버전을 확인했다.
- 질문은 시간 경과로 자동 응답하지 않는다. Codex 취소는 빈 답변을 보내지 않고 턴을 중단한다. 일부 질문의 답만 제출하지 않으며, 밀린 화면 상태를 먼저 반영하여 취소 대상 턴을 맞춘다. 질문 대기 중 오래된 상태 조회 결과로 대기를 끝내지 않는다.
- 확인 키를 누르고 있을 때 다음 질문까지 자동 선택되지 않게 한다. Ctrl+C는 질문을 취소하고, Ctrl+Enter·Shift+Enter·Alt+Enter가 답변을 제출하지 않게 한다. 질문의 직접 입력은 기존 단일 줄 표시를 유지한다.
