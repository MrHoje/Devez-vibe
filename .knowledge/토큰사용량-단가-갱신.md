# 토큰 사용량 비용($) 단가 — 갱신 프로세스

> 컴포저 상단 선에 표시되는 **추정 비용($) 의 모델별 단가**를 바꾸거나 새 모델을 추가할 때 보는 문서.
> "단가 최신화 해줘", "gpt-5.7 단가 넣어줘" 등에 이 절차를 따른다.
>
> DevezCode(`C:\Source\DevezCode\.knowledge\토큰사용량-단가-갱신.md`)와 **같은 단가표**를 쓴다.
> 한쪽 단가를 고치면 다른 쪽도 같이 고쳐야 두 도구가 같은 세션에 같은 금액을 낸다.
> 단, **표시 형태는 다르다** — DevezCode 는 `↓입력 ↑출력 ($비용)`, DevezCLI 는 금액만 보여준다
> (토큰량은 의도적으로 숨김). 토큰 수를 다시 노출하려면 `TokenTotals` 의 버킷을 그대로 쓰면 되고,
> 포맷터(`format_tokens`)는 이력에서 되살릴 수 있다.

## 구조 (어디서 뭐가 계산되나)

| 요소 | 위치 | 비고 |
|---|---|---|
| **내장 단가표** | `src/pricing.rs` 의 `PRICES` | `(모델 슬러그 부분일치, InPerM, OutPerM)`. **구체적인 티어를 먼저** 둔다 |
| **캐시 배수** | `src/pricing.rs` 의 `CACHE_WRITE_MULTIPLIER` / `CACHE_READ_MULTIPLIER` | 입력 단가 대비 write ×1.25, read ×0.1 |
| **비용 계산** | `pricing::estimate_usd()` | 표에 없는 모델이면 `None` → $ 를 아예 표시하지 않음 |
| **토큰 버킷 분리** | `pricing::TokenTotals::from_breakdown()` | app-server 의 `TokenUsageBreakdown` 파싱 |
| **누적값 수신** | `src/state.rs` 의 `"thread/tokenUsage/updated"` 처리 | `tokenUsage.total` → `token_totals` |
| **배지 조립** | `src/state.rs` 의 `estimated_cost()` | 포맷된 금액 문자열 하나만 렌더러에 전달 |
| **배지 표시·축약 순서** | `src/renderer.rs` 의 `fitting_badge_spans()` | `금액 · 모드 · Fast` 순서로 표시하되, 폭 부족 시 **금액 → Fast → 모드** 순으로 떨어짐(읽는 순서와 버리는 순서가 반대) |

- 단가 단위: **100만 토큰당 달러**(perM).
- **토큰 수는 app-server 실측값**(하드코딩 아님). **단가만** 가변.
- 단가는 `Match` 방식이 아니라 `model.contains(slug)` 단순 부분일치. 모델 슬러그는
  `AppState::selected_model_name()`(= `ModelInfo.model`, 예 `gpt-5.6-sol`)이다.

### DevezCode 와 다른 점 (중요)

DevezCode 는 `settings.json` 의 `UsagePricing` 으로 **재빌드 없이** 단가를 덮어쓸 수 있다.
**DevezCLI 에는 그 경로가 없다** — 단가 변경은 `PRICES` 배열 수정 + 재빌드가 유일한 방법이다.
재빌드 없이 바꿔야 할 일이 반복되면 `~/.codex/config.toml` 이나 별도 설정 파일에서 읽는
오버라이드를 추가하는 것을 검토한다(현재는 미구현 — 없는 기능을 있다고 쓰지 말 것).

## 갱신 방법

`src/pricing.rs` 의 `PRICES` 를 수정하고 `cargo test` → `cargo build --release`.

```rust
const PRICES: &[(&str, f64, f64)] = &[
    ("gpt-5.6-terra", 2.0, 12.0),
    ("gpt-5.6-luna",  0.2,  1.2),
    ("gpt-5.6",       5.0, 30.0),   // sol 및 티어 미표기 폴백
    ("gpt-5.5",       5.0, 30.0),
    ("gpt-5.3-codex", 1.75, 14.0),
    ("codex",         1.25, 10.0),
    ("gpt-5",         1.25, 10.0),
    ("claude-opus-5", 5.0, 25.0),
    // … Claude 나머지 티어
];
```

### ★ 순서가 곧 우선순위

`find()` 로 **위에서부터 첫 일치**를 쓴다. `("gpt-5.6", …)` 를 `("gpt-5.6-luna", …)` 보다 위에 두면
luna 가 폴백 단가($5/$30)로 새서 **6배 과대 계상**된다. 새 티어를 추가할 때는 반드시
더 긴(구체적인) 슬러그를 위에 넣고, `model_tiers_are_matched_before_the_generic_family` 테스트에
케이스를 추가한다. 이 테스트가 순서를 잠그는 장치다.

### ★ 단가 갱신 시 반드시 함께 점검 — 캐시 배수

`InPerM`/`OutPerM` 만 보지 말고 캐시 요율도 확인한다:

1. **입력·출력 단가** 최신값 (아래 "확인처")
2. **캐시 write 배수** — 현재 ×1.25 (GPT-5.6 부터 cache write 과금)
3. **캐시 read 배수** — 현재 ×0.1 (cached input)
4. 모델별로 요율이 갈리면 `PRICES` 를 `(slug, in, out)` 에서 배수까지 담는 튜플/구조체로 확장해야
   한다 — 현재 배수는 **전 모델 공통 상수**다

캐시 배수가 틀리면 캐시 비중이 큰 세션에서 금액이 크게 어긋난다(장시간 세션은 캐시 read 가
입력 토큰의 대부분을 차지한다).

## app-server 필드 해석 (여기서 실수하기 쉽다)

`thread/tokenUsage/updated` 알림의 `tokenUsage` 는 `ThreadTokenUsage` 다:

```ts
type ThreadTokenUsage = { total: TokenUsageBreakdown, last: TokenUsageBreakdown, modelContextWindow: number | null }
type TokenUsageBreakdown = { totalTokens, inputTokens, cachedInputTokens, cacheWriteInputTokens, outputTokens, reasoningOutputTokens }
```

| 값 | 쓰는 곳 | 이유 |
|---|---|---|
| `total.*` | **추정 비용** | 과금은 매 턴을 누적한다 |
| `last.totalTokens` | **`ctx:` 컨텍스트 게이지** | 현재 프롬프트가 점유한 양 |

- **`total` 을 컨텍스트 게이지로 쓰면 안 된다.** 누적값이라 몇 턴 만에 윈도우를 넘겨
  `ctx: 1103k/258k (426%)` 같은 표시가 나온다(실제로 겪은 버그).
- `inputTokens` 는 **cached·cache write 를 포함한 총계**다. 버킷별로 다른 단가를 매기려면 빼내야 한다:
  `input_new = inputTokens - cachedInputTokens - cacheWriteInputTokens`
- `reasoningOutputTokens` 는 `outputTokens` 의 **부분집합**이다. 더하면 출력이 이중 계상된다.
- 스키마 재확인: `codex app-server generate-ts --experimental --out <DIR>` (읽기 전용, 안전)

## 주의

- 비용은 **API 정가 환산 추정치**이며 실제 청구액이 아니다. ChatGPT 구독(Plus/Pro)으로 쓰면
  플랜 포함 쿼터로 처리되므로 결제액과 무관하다.
- 단가 미상 모델은 **금액을 생략**한다(0 으로 계산하지 않는다). 없는 단가를 추정하는 것이
  숫자를 안 내는 것보다 나쁘다. DevezCLI 는 금액만 표시하므로, 이 경우 배지 맨 앞
  세그먼트가 통째로 사라지고 `모드 · Fast` 만 남는다(토큰량으로 대체되지 않는다).
- 단가를 고치면 `cargo test` 의 다음 테스트가 깨진다 — 기대값을 **손으로 다시 계산해서** 갱신한다.
  깨진 값을 실제 출력으로 덮어쓰면 검증 장치가 사라진다.
  - `pricing.rs`: `model_tiers_are_matched_before_the_generic_family`,
    `cache_buckets_are_discounted_against_the_input_rate`
  - `state.rs`: `composer_badge_reports_an_estimated_cost_from_the_billed_totals`
