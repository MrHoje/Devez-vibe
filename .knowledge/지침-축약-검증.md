# 기본·역할 지침 축약 검증

최신 구성은 문서 끝의 **「사용 빈도 기준 재조정」** 절을 기준으로 한다. 현재 Planner만 단계별로 읽고, Goal Runner·Builder·Reviewer는 통합 본문을 사용한다. 아래의 이전 분리안과 계측값은 변경 이력이다.

- 작업일: 2026-09-09. 기준은 작업 시작 시 저장소 내용이며, 앞서 적용한 Builder의 일반 완료 보고 제한과 상세 분석 예외를 포함한다.
- 기본 지침 두 종류와 역할 본문 여덟 종류의 합계는 **26,343 → 12,475토큰**, **13,868토큰·52.6% 감소**다. 이 합계는 지침 원문의 관리 규모이며 한 요청에 모두 전달되는 양이 아니다.
- 반복 설명을 합치고 검토 계약의 불일치를 정리했다. 단계별 문서를 나중에 읽는 방식이나 새 의존성을 제품에 도입하지 않았으며, 각 역할은 필요한 지침을 그대로 전달받는다.
- 실제 모델의 준수율이 같거나 개선됐다는 검증은 하지 않았다. 아래 정적 사례 점검과 전달·갱신 검사 결과를 그 보장으로 해석하지 않는다.

## 검토 계약에서 바로잡은 부분

- 주 검토자와 하위 검토자의 새 결함·변경하지 않은 파일·생성 예정 파일·기존 경고 처리 기준을 일치시켰다.
- 판정 생성 측에도 `target`, 문제별 `id`, 재검토 `earlier.status`를 정의했다. Goal Runner는 검토 자료의 경로와 SHA-256을 전달하고 일치 여부를 대조하도록 했다. 자동 JSON 검사기를 새로 구현한 것은 아니며 모델이 따르는 계약을 정리한 것이다.
- 권한상 판정 파일을 쓸 수 없을 때 호출자가 원문을 저장하는 경로를 하위 검토·시험 지침에도 명시했다. 사용자에게는 한국어 판정을 쓰고 내부 구조화 기록만 코드를 유지한다.
- 모드 안내가 특정 제공자의 질문 도구만 지목하던 문구를 지원되는 질문 도구 안내로 바꿨다. 각 제공자의 실제 도구 이름은 제공자별 지침에 남겼다.

## 기존 설치본 갱신과 백업

- 변경 전 하위 본문은 이력 식별 파일로 보존하고 기존 갱신 대상 목록에 추가했다. 모델·추론 설정·사용자 추가 옵션은 유지하며 직접 수정한 지침은 갱신하지 않는다.
- 이전 갱신에서 만든 백업이 다른 내용을 담고 있으면 덮어쓰거나 갱신을 포기하는 대신 다음 번호의 백업을 만든다. 같은 내용의 백업은 재사용한다.
- 백업을 읽거나 쓸 수 없는 오류에서는 원본 지침을 교체하지 않는다. 기존 임시 파일 작성·동기화 후 교체 방식을 유지한다.
- `prompts/**/*.md`의 LF 규칙을 유지했다. 최초 검사에서 발견한 새 파일의 CRLF와 계획 인계 계약 표현 차이는 수정했다.

## Builder 중복 정리 재대조

같은 세션에서 공통 지침과 의미가 비슷하다는 이유로 Builder 문장을 넓게 삭제했다가 고유 조건이 빠졌다. 삭제 전 Builder 본문과 `src/main.rs`의 `DEVEZ_INSTRUCTIONS`, `CLAUDE_DEVEZ_INSTRUCTIONS`를 요구 단위로 다시 대조했다. OpenCode는 Codex 공통 지침을 사용하며, 세 제공자 모두 Builder 역할 본문을 전달받는다.

| 삭제 전 요구 | 공통 지침의 근거와 범위 | 최종 처리 |
| --- | --- | --- |
| 모든 답변을 가장 짧고 명확하게 전달 | 공통의 '중복을 줄이되'는 전체 답변의 간결성·명확성 기준과 같지 않음 | Builder에 복원 |
| 결론부터 쓰기 | 두 공통 지침의 '결론부터 한국어 불릿·코드 블록으로 쓴다' | 공통에서 적용 |
| 핵심 근거·사용자 영향·필요한 조치만 남기기 | 공통은 필요한 내용을 포함하도록 하지만, 다른 내용을 제외하는 '만' 조건은 명시하지 않음 | Builder에 복원 |
| 서론·맺음말 요약 생략 | 두 공통 지침의 '서론·인사·맺음말 요약·이모지는 쓰지 않는다' | 공통에서 적용 |
| 반복 설명 생략 | 공통의 중복 축소와 별개로, 복원한 Builder의 '전송 전에 같은 뜻의 문장과 불필요한 항목을 삭제한다'가 삭제 동작을 명시 | Builder의 전송 전 점검으로 함께 보존 |
| 요청하지 않은 부연 생략 | 공통에는 명시되지 않음. Builder의 기존 '묻는 범위만 답하고, 추가 설명은 요청받을 때 제공한다'가 같은 제한을 명시 | 기존 Builder 문장을 유지하고 같은 뜻의 문장은 반복하지 않음 |
| 단순 질문·완료 보고는 짧게 | 공통에는 해당 응답 유형의 길이 기준이 없음 | Builder에 유지 |
| 분석·설명·선택·승인은 판단에 필요한 만큼만 늘리기 | 공통의 선택·승인 분량 예외는 분석·설명을 포함한 이 기준과 같지 않음 | Builder에 복원 |
| 필요한 근거·미확인 범위 보존 | 두 공통 지침은 답변 유형에 관계없이 '판단에 필요한 근거·미확인 범위·후속 조치'를 남기도록 명시 | 공통에서 적용 |
| 위험·선택 결과를 분량 때문에 생략하지 않기 | 위험 보존은 공통에 명시되지 않음. 선택 결과 보존은 공통에서 선택·승인 답변에 한정되므로 분석·설명까지 같은 범위로 보장하지 않음 | 원래 적용 범위를 Builder에 복원 |
| 전송 전 중복 문장·불필요한 항목 삭제 | 공통의 중복 축소에는 '전송 전'이라는 점검 시점이 없음 | Builder에 복원 |
| 띄어쓰기 유지·서로 다른 쟁점의 억지 압축 금지 | 두 공통 지침의 '띄어쓰기를 없애거나 서로 다른 쟁점을 압축하지 않는다' | 공통에서 적용 |

공통 규칙과 Builder 구현 규칙은 이번 복원에서 수정하지 않는다. 역할 머리말은 현재 Builder 지침 적용과 공통 지침 준수만 안내한다. 지침 포함·전달 검사는 실제 모델의 준수율 검증과 구분한다.

검증: 고유 문구 보존, 선택한 역할의 턴 전달, 제공자별 공통 지침 전달, 세 제공자의 역할 수신, Codex 경계의 역할 보존에 대한 기존 검사 5개가 통과했다. Builder 구현 본문은 복원 전과 동일함을 대조했다. 실제 모델 응답의 준수율 검증과 배포는 수행하지 않았다.

### 2026-09-10 Planner·Goal Runner 출력 정규화

- Planner 최종 보고를 목표 → 주요 작업 → 검토 결과 → 미확정 사항 → 계획 경로로 고정했다. 해당 없는 항목은 생략하지만 검토 미실행·미확정 결정은 숨기지 않으며 실제 저장 경로만 쓴다. `Planner Handoff` 이하 승인 질문·옵션·실행 가능 조건·역할 전환 절은 변경 전후 원문이 일치한다.
- Goal Runner 최종 보고를 완료 여부 → 변경·영향 → 검증 → 남은 문제·조치로 고정했다. 첫 항목은 필수이며 이유·미충족 조건을 포함한다. 기존 실행 결정·틀렸을 때 영향, 검토 회차·독립성, 커밋 상태, 작업 공간·근거 경로, 산출물 정리 전 추적·제외 확인 조건을 네 항목에 재배치했다.
- 정적 사례 대조: Planner의 검토 미실행·미확정 결정은 해당 항목에 남고 실행 승인 게이트는 유지한다. 저장하지 않은 계획 경로는 생성하지 않는다. Goal Runner의 실패·권한 차단은 첫 항목에 미완료와 조건을 쓰고 마지막 항목에 다음 조치를 쓴다. 완료 후 잔여 문제가 없으면 마지막 항목은 생략한다. 이는 실제 모델 출력 준수율 검증이 아니다.
- 검증: 인계 관련 시험 22개와 세 제공자 역할 전달 시험 1개 통과, 변경 형식 검사 통과. 실제 모델 응답 비교·커밋·배포는 수행하지 않았다.

## 2026-09-10 사용 빈도 기준 재조정

### 최종 판단과 적용

- 사용자와 전 단계 사용 가능성을 다시 검토했다. Goal Runner는 구현·검토·검증·완료까지 진행하는 역할이므로 일반적인 완주에서 주요 절차를 모두 쓰는 편이라고 판단했다. 실제 사용 빈도 통계를 확보한 판단은 아니다. 초기 본문만 작게 만드는 것보다 완주 중 추가 문서 읽기를 줄이는 구성을 택했다.
- 위임·수정 반복만 별도 문서로 남기는 후보도 직접 작성해 계측했다. 공통으로 필요한 자격·검토 조건을 본문에 남기면 분리 가능한 세부 본문은 위임 **181토큰**, 수정 반복 **160토큰**이었다. 참조 안내·경로·분기 규칙과 조건 발생 시의 추가 읽기 비용을 고려하면 작은 절감에 비해 복잡성이 컸다. 조건부 문서도 남기지 않고 Goal Runner 전체를 통합했다.
- **Goal Runner:** 시작·구현·검토 계약·수정 반복·위임·최종 검증을 본문에 포함한다. 참조 파일 5개와 `GOAL_RUNNER_GUIDES` 연결을 제거했다. 정상 캐시 경로와 사용할 수 없는 캐시 경로 모두에서 같은 완전한 본문을 전달하며, 외부 절차 파일을 읽지 않는다.
- **Planner:** 요구 확인·계획 작성·검토/인계의 세 문서 분리를 유지한다. 인터뷰가 여러 턴에 걸치는 역할이라는 점을 반영했다. 본문과 참조 문서는 이번 재조정에서 변경하지 않았다.
- **Builder·Reviewer:** 본문을 유지한다. 기본 지침, Claude 리마인더, 기존 승인 조건과 보고 형식도 유지한다. Goal Runner에는 제공 기록 보고와 실제 파일 검증을 구분하고, 읽기 전용 요청에서 실행 기록 파일을 새로 만들지 않도록 하는 짧은 안내만 유지했다.
- 이전 분리안의 ‘Goal Runner 문서가 없으면 중단’은 더 이상 적용되지 않는다. 필요한 절차가 처음부터 전부 전달되므로 그 오류 경로 자체를 없앴다. Planner의 필요한 문서 준비·읽기 실패 처리와 다른 역할로 전환했을 때 이전 절차의 적용을 끝내는 규칙은 유지한다.
