# Memory Hub 외부 메모리 검수 보고서

## 판정

- 배포 대상: `1.7.82`
- 판정: 요구 범위 충족. 외부 프로젝트 메모리 수집, 제공자 공용 취합, 비동기 실행, 토큰 절감, 무알림 동기화와 활성 상태 표시를 확인했다.

## 동작 범위

- Claude가 DevezVibe 밖에서 만든 프로젝트별 `MEMORY.md`를 읽기 전용으로 수집한다.
- Codex가 만든 메모리는 읽기 전용 데이터베이스에서 가져오며, 해당 세션의 작업 경로가 현재 프로젝트 아래이거나 GitHub `origin`이 같을 때만 포함한다.
- OpenCode와 Grok은 별도 자동 메모리 저장소를 제공하지 않으므로 프로젝트 규칙 파일을 중복 복사하지 않는다. DevezVibe 안에서 완료한 작업은 제공자와 관계없이 계속 공용 메모리에 포함한다.
- GitHub `origin`이 없는 프로젝트는 인증 조회, 분석과 동기화를 시작하지 않으며 오류도 표시하지 않는다.

## 지연과 토큰 사용

- 원격 다운로드, 순정 CLI 데이터베이스 조회, 분석, 업로드와 로그아웃 정리는 모두 화면 입력과 분리된 백그라운드 경로에서 실행한다.
- 실행 중 외부 메모리는 60초 간격으로 확인하고, 내용 지문이 바뀐 경우에만 다시 분석한다.
- 일반 작업은 최대 5개 턴 또는 첫 기록 후 5분 단위로 묶는다. 대기 기록은 앱 데이터에 먼저 저장해 다음 실행에서도 복구한다.
- 동기화 성공 알림은 표시하지 않는다. 허브가 실제로 동작하는 프로젝트에서만 컴포저의 `VibeMode` 오른쪽에 `MemoryHub`를 표시한다.

## 안전 점검

- 외부 메모리는 분석 전에 토큰, 비밀번호, 인증 헤더와 개인 키 형태를 제거한다.
- Claude 파일은 심볼릭 링크를 거부하고, Codex 데이터베이스는 심볼릭 링크가 아닌 최신 버전 파일만 읽기 전용으로 연다.
- 외부 입력과 결과에는 크기 제한을 적용하며, 다른 프로젝트의 Codex 메모리가 섞이지 않는 합성 데이터베이스 검사를 통과했다.
- Codex 데이터베이스 형식이 바뀌면 해당 소스만 제외하고 경고하며 Claude 메모리와 기존 공용 메모리는 계속 동작한다.

## 검증 결과

- `cargo test`: 1,211개 통과, 실제 GitHub 인증을 만드는 1개 검사만 의도적으로 제외, 실패 0개.
- `cargo clippy --bin dvz`: 이번 변경에서 새 경고 없음. 기존 렌더러 구조와 미사용 항목에 관한 경고 20개는 관련 범위가 아니어서 유지했다.
- 수정한 메모리 모듈의 형식 검사와 `git diff --check`를 통과했다.
- 성공 알림 문구와 GitHub `origin` 누락 오류 문구가 실행 경로에 남지 않은 것을 검색으로 확인했다.

## 남은 제한

- Codex의 메모리 데이터베이스는 공개 문서 계약이 아니므로 향후 형식이 바뀔 수 있다. 형식 불일치 시 데이터 손상 없이 해당 가져오기만 중단하도록 방어했다.
- 순정 CLI에서 삭제한 과거 지식은 공용 메모리에서 자동 삭제하지 않는다. 여러 기기와 제공자에서 얻은 동일 지식의 출처가 사라질 수 있어, 삭제를 전파하려면 출처별 삭제 기록과 사용자 확인 기능이 필요하다.
- 여러 기기가 같은 프로젝트 메모리를 정확히 동시에 갱신하는 경우 GitHub 저장소의 파일 이력은 남지만 의미 단위 자동 병합은 보장하지 않는다. 실제 충돌 사례가 생기면 파일별 불변 기록 방식이 필요하다.
