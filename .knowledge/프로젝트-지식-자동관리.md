# 프로젝트 지식 자동 관리

## 저장 범위

- 지식 관리 모드는 기본적으로 꺼져 있으며 코드베이스 루트별로 유지한다. 같은 프로젝트의 다른 세션과 제공자는 같은 설정을 읽는다.
- 자동 지식 구현은 보존하지만 현재 런타임에서는 항상 Off로 고정한다. 저장된 설정과 기존 자동 지식이 있어도 분석하거나 주입하지 않는다.
- `/knowledge` 명령과 Knowledge 화면 표시·클릭 진입점은 노출하지 않는다.
- 자동 생성 지식은 `.knowledge/auto/MEMORY.md`, 주입용 요약은 `.knowledge/auto/SUMMARY.md`에 저장한다.
- `.knowledge/` 루트의 기존 문서는 사용자가 관리하는 지식이다. 자동 관리 기능은 해당 문서를 수정하지 않는다.
- 중단 복구용 작업 기록과 잠금은 DevezVibe 앱 데이터에만 임시 저장하며, 처리된 작업은 제거한다. 프로젝트별 대기 작업은 32개로 제한하고 손상·반복 실패 기록은 격리한다.

## 실행 시점과 모델

- 성공한 기본 대화가 끝났을 때만 작업 기록을 백그라운드 분석 대기열에 넣는다. 실패·취소·`/btw` 대화와 제공자가 종료 상태를 알려주지 못한 턴은 제외한다.
- 마지막 제공자가 Codex이면 `gpt-5.6-luna`, Claude이면 `haiku`, OpenCode이면 마지막으로 사용한 모델을 그대로 사용한다.
- 분석 실행은 기존 대화에 이어 붙이지 않으며 세션을 영구 저장하지 않는다. OpenCode의 분석 세션도 결과 회수 후 삭제한다.
- 제공자가 실패해도 다른 모델로 대체하지 않는다. 최대 세 번의 다음 실행에서 다시 시도한 뒤 작업 기록을 제거한다.

## 지식 품질과 안전

- 확정된 설계 결정, 반복 가능한 절차, 재발 가능한 실수, 검증된 원인과 해결법만 보존한다.
- 자동 장기 지식은 12,000자, 주입용 요약은 3,000자를 넘기지 않는다. 기존 장기 지식이 한도를 넘으면 일부를 잘라 덮어쓰지 않고 갱신을 중단한다.
- 새 작업 기록과 기존 자동 지식 모두 모델에 보내기 전에 일반적인 API 키, 토큰, 인증 헤더, 비밀번호, 개인 키 형태를 제거한다.
- 여러 DevezVibe 세션이 같은 프로젝트를 갱신할 때는 프로젝트별 잠금으로 중복 분석과 덮어쓰기를 방지한다.
- 프로젝트별 모드 설정과 분석 대기열은 복구 가능한 임시 파일 교체 방식으로 저장한다.
- `.knowledge`, `.knowledge/auto`, `MEMORY.md`, `SUMMARY.md` 중 하나라도 심볼릭 링크이면 자동으로 읽거나 기록하지 않는다.
- 제공자 표준 출력과 오류 출력은 각각 1MiB까지만 보관하고 나머지는 비우면서 읽어 프로세스 정지와 메모리 증가를 막는다.

## 주입 규칙

- 지식 모드가 켜진 턴에는 `SUMMARY.md`와 `.knowledge` 아래 파일 색인만 전달한다.
- 모든 문서 본문을 매번 넣지 않고 현재 작업과 관련된 문서만 에이전트가 선택해서 읽는다.
- 현재 저장소와 사용자 지시가 수동 지식보다 우선하며, 수동 지식이 자동 생성 지식보다 우선한다.
