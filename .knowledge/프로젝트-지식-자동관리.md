# 프로젝트 지식 자동 관리

## 저장 범위

- `/memory-hub`에서 GitHub 로그인을 마치면 지식 관리가 켜지고, 로그아웃하면 꺼진다.
- 같은 프로젝트의 모든 DevezVibe 제공자 세션은 동일한 자동 지식과 주입용 요약을 읽는다. OpenCode에 연결된 Grok 등 새 제공자도 같은 완료 이벤트를 거쳐 자동으로 포함된다.
- GitHub `origin`의 소유자와 저장소 이름을 프로젝트 키로 사용한다.
- 자동 생성 지식과 주입용 요약의 로컬 캐시는 저장소 밖의 DevezVibe 앱 데이터에 저장해 소스 커밋과 분리한다.
- 두 자동 파일은 사용자 계정의 private `dvz-memory-hub` 저장소 아래 프로젝트별 폴더와 백그라운드 동기화한다.
- `.knowledge/` 루트의 기존 문서는 사용자가 관리하는 지식이다. 자동 관리 기능은 해당 문서를 수정하지 않는다.
- 중단 복구용 작업 기록과 잠금은 DevezVibe 앱 데이터에만 임시 저장하며, 처리된 작업은 제거한다. 프로젝트별 대기 작업은 32개로 제한하고 손상·반복 실패 기록은 격리한다.

## 실행 시점과 모델

- 성공한 기본 대화가 끝났을 때만 작업 기록을 백그라운드 분석 대기열에 넣는다. 실패·취소·`/btw` 대화와 제공자가 종료 상태를 알려주지 못한 턴은 제외한다.
- 마지막 제공자가 Codex이면 `gpt-5.6-luna`, Claude이면 `haiku`, OpenCode이면 마지막으로 사용한 모델을 그대로 사용한다. 이 구분은 분석 실행에만 쓰며 저장 결과에는 제공자 구분을 남기지 않는다.
- Claude의 저장소별 자동 `MEMORY.md`는 현재 프로젝트 지식에 읽기 전용으로 가져와 공용 메모리에 합친다. 프로젝트 범위를 안전하게 확인할 수 없는 제공자의 전역 메모리는 자동 업로드하지 않는다.
- 분석 실행은 기존 대화에 이어 붙이지 않으며 세션을 영구 저장하지 않는다. OpenCode의 분석 세션도 결과 회수 후 삭제한다.
- 제공자가 실패해도 다른 모델로 대체하지 않는다. 최대 세 번의 다음 실행에서 다시 시도한 뒤 작업 기록을 제거한다.

## 지식 품질과 안전

- 확정된 설계 결정, 반복 가능한 절차, 재발 가능한 실수, 검증된 원인과 해결법만 보존한다.
- 제공자별로 같은 사실이 반복되거나 표현만 다른 경우 의미 기준으로 하나로 합친다.
- 자동 장기 지식은 12,000자, 주입용 요약은 3,000자를 넘기지 않는다. 기존 장기 지식이 한도를 넘으면 일부를 잘라 덮어쓰지 않고 갱신을 중단한다.
- 새 작업 기록과 기존 자동 지식 모두 모델에 보내기 전에 일반적인 API 키, 토큰, 인증 헤더, 비밀번호, 개인 키 형태를 제거한다.
- 여러 DevezVibe 세션이 같은 프로젝트를 갱신할 때는 프로젝트별 잠금으로 중복 분석과 덮어쓰기를 방지한다.
- 프로젝트별 모드 설정과 분석 대기열은 복구 가능한 임시 파일 교체 방식으로 저장한다.
- `.knowledge`, 앱 데이터의 자동 지식 폴더, `MEMORY.md`, `SUMMARY.md` 중 하나라도 심볼릭 링크이면 자동으로 읽거나 기록하지 않는다.
- GitHub 토큰은 Windows Credential Manager의 DevezVibe 전용 항목에 보관하고 provider와 Git 자식 프로세스에는 전달하지 않는다.
- 계정을 바꾸거나 로그아웃하면 이전 계정의 로컬 자동 지식을 제거하고 원격 private 저장소는 보존한다.
- 제공자 표준 출력과 오류 출력은 각각 1MiB까지만 보관하고 나머지는 비우면서 읽어 프로세스 정지와 메모리 증가를 막는다.

## 주입 규칙

- 지식 모드가 켜진 턴에는 `SUMMARY.md`와 `.knowledge` 아래 파일 색인만 전달한다.
- 모든 문서 본문을 매번 넣지 않고 현재 작업과 관련된 문서만 에이전트가 선택해서 읽는다.
- 현재 저장소와 사용자 지시가 수동 지식보다 우선하며, 수동 지식이 자동 생성 지식보다 우선한다.

## GitHub OAuth App 배포 설정

- Device Flow를 켜고 `repo` scope를 승인받아 private 저장소 생성과 파일 동기화에 사용한다.
- 공개 client ID는 실행 파일에 포함한다. 사용자 실행 환경과 기존 Git 자격증명에서는 읽지 않는다.
- client secret은 생성하거나 실행 파일에 포함하지 않는다.
