# 컨텍스트 표시 복원 기준

확인 위치: [src/state.rs](../src/state.rs), [src/rollout.rs](../src/rollout.rs), [src/open_code.rs](../src/open_code.rs), [Claude 브리지](../npm/bridge/claude-agent-sdk-bridge.mjs). 비용용 누적 원장과 표시 여부는 [비용 계산 문서](토큰사용량-단가-갱신.md)에서 구분한다.

첫 프롬프트 전과 세션 재개 직후의 `ctx:` 표시는 provider가 다음 턴을 마칠 때까지 기다리지 않고, 이미 가진 설정과 저장 기록으로 채운다. 과거에 Codex rollout만 보완했다가 가시 세션 ID와 설정 상한, OpenCode 재생 사용량을 놓쳐 같은 증상이 재발했다.

## 값의 의미

- 사용량은 `tokenUsage.last.totalTokens`를 쓴다. 누적 과금값인 `tokenUsage.total`은 컨텍스트 사용량으로 쓰지 않는다.
- 상한은 `tokenUsage.modelContextWindow`를 우선하고, 아직 사용량 알림이 없을 때만 모델 카탈로그 값을 쓴다.
- Codex의 루트 `model_context_window` 설정은 모델 캐시의 기본 상한보다 우선한다. Claude와 OpenCode 모델에는 Codex 설정을 적용하지 않는다.

## provider별 복원 경로

| provider | 새 세션 상한 | 재개 직후 사용량 |
| --- | --- | --- |
| Codex | 모델 캐시를 읽은 뒤 루트 `model_context_window`로 덮어쓴다. | 활성 Codex 원본 ID의 rollout에서 마지막 `token_count`를 읽는다. 가시 세션 ID로 rollout을 찾지 않는다. |
| Claude | 브리지 모델 카탈로그의 `contextWindow`를 쓴다. | 브리지가 저장 transcript의 마지막 주 대화 사용량을 합쳐 `tokenUsage`로 반환한다. |
| OpenCode | 모델 카탈로그의 `contextWindow`를 쓴다. | `session/load` 중 재생되는 마지막 `usage_update`를 대화 조각과 함께 보존해 재개 응답의 `tokenUsage`에 넣는다. |

저장 기록에 사용량 자체가 없는 세션은 정확한 사용량을 만들 수 없으므로 0으로 남을 수 있다. 기록이 있는데도 재개 직후 0이고 다음 프롬프트 뒤 정상화된다면 복원 경로가 끊긴 회귀로 본다.

## 변경 시 검증

- Codex 설정 상한은 Codex 모델만 덮어쓰며 Claude와 OpenCode 값은 유지되는지 확인한다.
- 직접 실행 재개와 `/resume`이 모두 활성 Codex 원본 ID를 사용하는지 확인한다.
- Codex rollout, Claude transcript, OpenCode `session/load`의 저장 사용량이 다음 프롬프트 없이 상태에 적용되는지 확인한다.
- provider별 단위 테스트와 Claude 브리지 자체 검증 뒤 전체 `cargo test`를 실행한다.
