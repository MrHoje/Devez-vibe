## 방법과 범위

`ac99985`의 인덱스에 등록된 13개 문서를 대상으로 작성자가 질문 10개, 검색어, 기대 문서를 정한 뒤 실제 `rg` 검색을 실행했다. 문서를 미리 읽고 만든 자체 점검이므로 독립 평가나 실제 사용자 질문 분포를 대표하지 않는다.

`evaluate.ps1`은 질문에 포함된 단어를 정규식 OR 조건으로 검색한다. 색인 제목·설명에서 기대 문서가 후보에 포함되는지, 전체 문서 검색에서는 포함되는지를 별도로 계산한다. 별도 순위 알고리즘이나 임베딩은 사용하지 않는다. 현재 앱의 검색 함수를 시험한 것이 아니라 LLM이 사용할 수 있는 파일 검색 경로의 작은 기준선이다.

## 판단과 한계

아래 판단은 정비 전 시험 시점이다. 후속 요청으로 색인·문서를 보완했으며 변경 범위와 재시험은 [전체 문서 점검](document-audit.md)에 기록했다. 원본 결과는 덮어쓰지 않았다.

먼저 해당 문서의 색인 설명에 주요 증상을 반영하고, 색인에서 확신이 없으면 본문 검색으로 보완하는 접근을 권한다. 이번 작업은 평가만 하며 해당 설명이나 앱의 검색 지침을 바꾸지 않는다. 현재 표본에는 본문 검색으로도 회수하지 못한 사례가 없어 임베딩 도입의 실익을 증명하지 못했다. 관계를 여러 단계 추적하는 질문은 시험하지 않아 그래프 효과도 미측정이다.

실제 Claude·Codex의 읽기 준수율, 동의어·오타·부정 질문, 존재하지 않는 정보에 대한 응답, 더 큰 문서 집합의 품질·비용·지연은 미검증이다. 임베딩과 비교한 결과도 아니다.

## 재실행

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File artifacts/knowledge-search-evaluation/evaluate.ps1
```

`results.json`은 정비 전 원본 결과로 보존한다. 재실행은 `results-current.json`에 질문·검색어·기대 문서·후보·첫 일치 행과 색인 SHA-256을 저장한다. 이후 문서나 인덱스가 바뀌면 결과도 달라질 수 있다. Windows PowerShell 5.1의 한글 스크립트 파싱을 위해 스크립트는 UTF-8 BOM으로 저장한다.
