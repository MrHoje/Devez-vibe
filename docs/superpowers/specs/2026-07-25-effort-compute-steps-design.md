# `/effort` Compute Steps 디자인

## 목적

`/effort`의 가로 단계 선택과 키보드 조작은 유지하면서, Claude Code와 닮은
`Faster—Smarter` 축과 삼각형 마커를 Devez 고유의 단계형 표현으로 교체한다.

## 범위

- `/effort` 피커의 시각 표현만 변경한다.
- 모델 피커에서 함께 표시되는 effort 선택에도 같은 컴포넌트를 사용한다.
- 서버가 제공한 effort 순서와 지원 목록을 그대로 사용한다.
- 상태 저장, 모델 적용, 키 입력 처리와 색상 팔레트는 변경하지 않는다.

## 화면 구성

일반 폭에서는 모든 단계를 전체 이름으로 한 줄에 표시한다.

```text
low › medium › HIGH › xhigh › max › ultra
```

- 선택된 단계만 대문자 컬러 토큰으로 표시한다.
- 토큰은 현재 단계의 기존 `Tone::Effort*` 색상을 사용한다.
- 선택 토큰 바로 다음의 `›`도 같은 색상으로 칠해 진행 방향을 암시한다.
- 나머지 단계와 구분자는 muted 톤을 사용한다.
- `Faster`, `Smarter`, 수평선, `▲` 마커는 제거한다.

가용 폭이 전체 이름 표기에 부족하면 다음 약어를 사용한다.

```text
L › M › HIGH › XH › MAX › U
```

선택된 단계는 약어 대신 전체 이름을 유지한다. 압축 표기로도 들어가지 않는 폭에서는
현재 렌더러의 잘림 규칙을 따르며 별도의 스크롤이나 두 줄 배치는 추가하지 않는다.

## 상호작용

- `←`와 `→`로 이전·다음 effort를 선택한다.
- `Enter`로 적용하고 `Esc`로 취소한다.
- `/effort LEVEL` 직접 적용 방식은 변경하지 않는다.
- 모델이 지원하지 않는 effort는 렌더링하지 않는다.
- 선택 인덱스가 목록 범위를 벗어나면 기존처럼 마지막 유효 단계로 제한한다.

## 구현 경계

`EffortSlider` 데이터 구조와 상태 로직은 유지한다. 렌더러의
`effort_slider_lines`를 단계 토큰 생성 함수로 교체하고, 폭에 따라 전체 이름 또는
약어를 선택한다. 모델 피커와 effort 피커는 동일한 렌더링 경로를 계속 공유한다.

## 오류 처리

- effort 목록이 비어 있으면 현재처럼 추가 행을 렌더링하지 않는다.
- 알 수 없는 effort 이름은 `Tone::Accent`로 폴백한다.
- Unicode 구분자 `›`의 폭은 `unicode-width` 기준으로 계산한다.

## 검증

- 일반 폭에서 지원 effort가 순서대로 모두 표시되는지 검사한다.
- 선택 단계만 대문자·굵게·effort 색상으로 표시되는지 검사한다.
- 좁은 폭에서 비선택 단계가 지정된 약어로 바뀌는지 검사한다.
- 선택 단계의 전체 이름이 좁은 폭에서도 유지되는지 검사한다.
- 빈 목록과 범위를 벗어난 선택 인덱스가 패닉 없이 처리되는지 검사한다.
- 모델 피커와 `/effort` 피커가 같은 단계형 표현을 사용하는지 검사한다.
