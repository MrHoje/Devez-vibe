# 사용자 정의 에이전트 역할

## 무엇이 달라졌나

역할(Builder·Planner·Advisor·Goal Runner)은 바이너리에 고정돼 있었다. 이제 앱 전용 폴더에
파일을 두면 그 역할이 상태줄·역할 선택 창·`/agent`·Tab 순환에 함께 실린다. 빌드를 다시 하지
않고 역할을 늘릴 수 있다.

내장 네 역할은 그대로다. 이름·설명·색·순서가 바뀌지 않고, 사용자 정의 역할은 언제나 그 뒤에
붙는다. 정의 파일이 없으면 목록은 예전과 완전히 동일하다.

## 정의 파일

### 위치

```
%APPDATA%\DevezVibe\agents\<id>.md
```

`.md` 파일 하나가 역할 하나다. 폴더가 없어도 오류 없이 넘어간다.

### 규격

```markdown
---
label: QA Tester
detail: 한 줄 설명. 역할 선택 창의 오른쪽 열에 그대로 나온다.
---
여기부터 본문. 그 역할로 보내는 턴에 이 내용이 지침으로 붙는다.
```

| 항목 | 출처 | 없을 때 |
|---|---|---|
| 역할 id | 파일 이름(확장자 제외, 소문자로) | 파일 이름이 비면 제외 |
| 표시 이름 | 앞머리의 `label` | 파일 이름을 그대로 쓴다 |
| 한 줄 설명 | 앞머리의 `detail` | `사용자가 정의한 역할입니다.` |
| 역할 지침 | 앞머리 뒤 본문 | 본문이 비면 역할로 싣지 않는다 |

앞머리(`---` 두 줄)는 없어도 된다. 그때는 파일 전체가 본문이 되고 표시 이름은 파일 이름이 된다.

### 목록에 실리는 규칙

- 파일 이름 순으로 읽는다. 순서를 정하려면 파일 이름을 그렇게 지으면 된다.
- 내장 역할의 id(`builder`·`planner`·`advisor`·`goal-runner`)와 같은 이름은 무시한다.
  파일이 내장 역할을 덮어쓰는 일은 생기지 않는다.
- 본문이 빈 파일은 역할이 아니다. 이름만 뜨고 지침이 없는 역할은 만들지 않는다.
- 파일은 실행 시작에 한 번 읽는다. 정의를 고치거나 새로 넣었으면 앱을 다시 시작해야 보인다.

## 쓰는 방법

- 상태줄의 역할 이름을 누르거나 `/agent`를 인자 없이 실행하면 선택 창이 열린다. 숫자키는 1~9까지
  받는다.
- `/agent <id>`로 바로 고를 수 있다. 인자를 틀리면 안내에 실제 역할 목록이 그대로 나온다.
- Tab은 내장 네 역할을 지나 사용자 정의 역할까지 돌고 Builder로 돌아온다.
- 색은 특화 역할 세 색을 순서대로 돌려 쓴다. 사용자 정의 역할도 Builder와 구분돼 보인다.

역할을 고른 턴에는 지침 블록이 실려 나가고, Builder로 돌아오면 이전 역할을 물리는 블록이 한 번
나간다. 이 동작은 내장 역할과 같다. 응답 길이 제한은 역할 출력에서 완화되고 언어·서식 규칙은
유지된다.

## 이식 배치 파일

`QA-Tester-역할-이식.bat`(바탕화면)은 전역 폴더에 있는 QA 관련 에이전트 정의를 찾아 위 규격으로
바꿔 전용 폴더에 넣는다.

- 찾는 곳: `%USERPROFILE%\.claude\plugins`의 각 플러그인 `agents` 폴더, `%USERPROFILE%\.claude\agents`.
- 고르는 순서: 이름이 `qa-tester`로 끝나는 정의를 먼저 보여주고, 후보가 여럿이면 번호로 고른다
  (엔터는 1번).
- 만드는 것: `qa-tester.md` 하나. 표시 이름은 `QA Tester`로 고정하고, 한 줄 설명은 원본 정의의
  `description`에서 가져와 60자로 자른다. 본문은 원본 본문을 그대로 옮긴다.
- 이미 있으면 덮어쓸지 묻는다.

배치 파일은 자기 안에 든 PowerShell 부분을 임시 파일로 떼어내 실행한다. 콘솔 창에서 바로
결과를 읽을 수 있다.

## 주의할 점

- 서브에이전트용으로 쓴 정의를 그대로 옮기면 문구가 어긋날 수 있다. 역할은 메인 대화에서
  동작하므로 "사용자에게 직접 물을 수 없다" 같은 전제는 맞지 않는다. 옮긴 뒤 본문을 한 번
  읽어보는 편이 좋다.
- 도구 권한·모델 지정은 역할의 개념에 없다. 원본 정의의 그런 항목은 옮겨지지 않고 버려진다.
- 역할 수가 많아지면 상태줄과 선택 창이 길어진다. 실제로 쓰는 역할만 두는 편이 낫다.
